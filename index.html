What the build history shows

1

Intermediate builds are most of the work

A final release usually followed many QA and review iterations that never appear in the release list.

2

Review-driven work is substantial

Design review, product review, Store-review changes, content changes and TL review repeatedly generated new builds.

3

Localization arrives in waves

Initial localization, new-screen localization, notification localization and remaining language bugs each came as separate builds.

4

Monetization drives iteration

A/B onboarding, Premium and Offer screens, hard paywalls, Qonversion, pricing presentation, Rating Review and purchase tagging recur everywhere.

5

Backend issues cause iOS rebuilds

Upkee, Caloric, ResumeIT and Locate US all show infrastructure or sync-driven follow-up builds.

6

“Testing done” is not “released”

Threads often continued with product or design review, or another build, after QA had already passed.

Separate original scope, added scope, engineering completion, QA and review changes, dependency work and final release. Only then can genuine engineering slippage be told apart from review cycles and post-release stabilization.

08 — Learnings

What We Learned

Three patterns across the quarter, and two incidents that changed how we work.

1

Work after release was big

Upkee, Printer, ResumeIT, Locate US, CleanPath and Ad Blocker kept changing after their first delivery.

2

Backend issues forced extra builds

Cloud Functions fixes drove new builds for ResumeIT, Caloric and PDFEditor.

3

Monetization tests were everywhere

Premium and offer screens, CPP, pricing and A/B tests across seven apps.

Learning from our mistakes

Incident 1 • Gemini Pro model build
API costs built up unnoticed

Gemini API usage wasn’t being checked regularly, so the bill grew before anyone caught it.

Unmonitored API usage
API secured remotely: developers get a reference, never the raw key
Automated daily API usage alerts
Cloud Functions moved to a separate project, so keys change without affecting other apps
Clear usage flow and faster leak detection
Incident 2 • FM Radio
A cloud VM ran for weeks

An AI agent was given full cloud access. A virtual machine it started was left running for weeks and added to our bill.

Agent with full cloud access
AI agents no longer get full cloud access
Developers review every change an agent makes
Agents ask permission before turning on any paid service
